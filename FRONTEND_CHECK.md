# Проверка React + FastAPI: demo-0.2

Фронтенд Ксюши принят из frontend.zip и подключен к реальному API. Текущий продукт сохраняет 6–24 месяца, фиксированные 24% годовых и три категории цели. Диапазон 6–60 месяцев, индивидуальная ставка и влияние цели на условия отложены и не реализованы в этом изменении. Docker остается задачей Димы по [DOCKER_HANDOFF.md](DOCKER_HANDOFF.md), расширенный набор Валеры пока не получен.

## 1. Подготовка backend

Команды ниже выполнять из корня проекта. Нужны настроенный игнорируемый .env и работающая PostgreSQL; инструкции первого запуска — [BACKEND.md](BACKEND.md). Существующий .env не перезаписывать. После обновления исходников применить миграцию:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m credit_cabinet.seed --check-only
```

Текущая вершина — 0004_draft_archive. Она добавляет applications.archived_at и событие DRAFT_ARCHIVED; существующие заявки и пароли не сбрасывает. На ноутбуке Сергея эта миграция уже применена; повторный upgrade безопасен. У остальных участников она применяется к их собственной БД.

Если исходный набор еще не импортирован, выполнить `python -m credit_cabinet.seed` тем же интерпретатором. Для новых аккаунтов CLI скрыто запросит пароль; существующие email/пароли сохранит. Демологины: client@example.com (C01), client2@example.com (C02), bank@example.com и bank2@example.com. Пароли использовать заданные при подготовке своей БД; общего опубликованного пароля реального API нет.

В .env backend должны быть разрешены точный origin http://localhost:5173 и локальные HTTP-cookie (COOKIE_SECURE=false). В .env.example это уже предусмотрено. Для восстановления неистекшей сессии между перезапусками сохранять CSRF_SIGNING_KEY, БД и cookie браузера.

## 2. Запуск двумя терминалами

В первом терминале из корня:

```powershell
.\.venv\Scripts\python.exe -m credit_cabinet
```

Swagger — http://localhost:8000/docs, GET /health/ready должен вернуть 200 и schema_revision=0004_draft_archive.

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Нужны Node.js ^20.19.0 либо >=22.12.0 и npm; проверено на Node.js 24.19.0/npm 11.6.2. npm ci устанавливает версии из package-lock.json. Открыть именно http://localhost:5173. Не смешивать localhost и 127.0.0.1: это разные origin/cookie. Порт фиксирован; второй Vite на занятый 5173 не запустится.

В среде Codex на текущем ноутбуке есть комплектный Node, а отдельного npm в PATH нет. Для Сергея подготовлен локальный npm в игнорируемой .tools. В обычном PowerShell комплектный Node может отсутствовать в PATH. Вместо команд второго терминала можно из корня выполнить (PATH меняется только в этом терминале):

```powershell
$frontendNodeDir = 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin'
$env:Path = "$frontendNodeDir;$env:Path"
node .tools/npm-bootstrap/node_modules/npm/bin/npm-cli.js --prefix frontend ci --ignore-scripts --no-audit --no-fund
node .tools/npm-bootstrap/node_modules/npm/bin/npm-cli.js --prefix frontend run dev
```

Эта .tools не входит в Git/Docker и не является зависимостью поставки; другим участникам нужен свой Node/npm. Зависимости frontend на этом ноутбуке уже установлены, повторный ci нужен после обновления lock-файла или для чистой проверки.

По умолчанию UI обращается к настоящему API через Vite proxy /api и /health → localhost:8000. Фронтовой .env для стандартного запуска не нужен. CSRF и cookie обрабатывает API-клиент: вручную копировать токен из Swagger не требуется. Если появляется ORIGIN_FORBIDDEN, проверить ALLOWED_ORIGINS backend и перезапустить API.

## 3. Клиент, сохранение и удаление

1. Войти как client@example.com со своим паролем. На обзоре видны компания C01 и продукт. Нажать «Подобрать финансирование».
2. Выбрать закупку товара, ввести 1000000 и 12 месяцев. Дождаться «Сохранено», обновить страницу: поля и шаг восстановились. Закрывать вкладку безопасно после подтвержденного сохранения; последние несохраненные символы не гарантируются.
3. Подтвердить «Потребность», пройти «Компания» и «Финансы», на «Проверка» явно отметить оба подтверждения. Фронт не назначает их автоматически. Без согласия БКИ доступны только расчетные показатели, без риска и маршрута.
4. Открыть ИИ-помощника, выполнить объяснение или сравнение. При недоступной/выключенной модели виден явный шаблонный FALLBACK; это не успешная генерация LLM. Фронт не включает собственную модель в рабочем режиме. Отчет не отправляет заявку.
5. Скачать C01.csv; затем подтвердить «Проверка» и отправить заявку. Для C01/1 млн/12 месяцев ожидается APPROVED, риск-балл 10 и платеж 94559.60. Основные карточки округляют отображение рублей, backend хранит копейки; подробный банковский расчет показывает их.
6. В «Мои заявки» создать еще один черновик и удалить его через подтверждение. Он исчезнет из списка; старая ссылка даст «Заявка не найдена». Отправленную заявку удалить нельзя. Удаление разрешено представителю с доступом к компании, не только автору черновика.
7. Для конфликта открыть один черновик в двух вкладках. В первой сохранить изменение, во второй изменить поле. Вторая покажет конфликт и остановит автосохранение. «Загрузить актуальную версию» явно отбросит несохраненные местные правки; автоматической перезаписи нет.

Неполные финансы не блокируют отправку сами по себе: backend создаст NEEDS_INFO. До дозапроса таблица профиля доступна на чтение; после него запрошенные значения, включая отсутствующий месяц, можно заполнить. Пропуски не превращаются в нули. Правки сохраняются в заявке, исходные CSV не переписываются.

## 4. Банковский цикл на существующем C01

1. Под клиентом создать отдельную заявку C01 на 2500000, 12 месяцев, закупку товара. Подтвердить страницы и отправить: ожидается MANUAL_REVIEW, риск-балл 40.
2. Выйти, войти как bank@example.com. В очереди открыть эту заявку. Видны отправленный снимок, расчеты, результаты проверок, история и документы. Клиентские неотправленные изменения банк не получает.
3. Нажать «Запросить уточнение», написать сообщение минимум 20 символов и выбрать «Описание цели». Отправить запрос: NEEDS_INFO.
4. Под клиентом открыть заявку, нажать «Дополнить сведения», на «Потребность» добавить пояснение. Подтвердить страницы и отправить повторно. Появится отправка 2, первоначальный снимок сохранится.
5. Под сотрудником открыть актуальную карточку, выбрать «Одобрить», заполнить публичное обоснование, при необходимости внутренний комментарий, явно подтвердить окончательность и нажать «Одобрить». Условия берутся из снимка, вручную ставка/сумма не меняются.
6. Клиент увидит APPROVED и публичное обоснование. Внутренний комментарий доступен только банку. Во вкладке версий сотрудника сохранены обе отправки.

Для финансовых исключений/технического повтора использовать [BANK_CHECK.md](BANK_CHECK.md) и [SUBMISSION_CHECK.md](SUBMISSION_CHECK.md). Дополнительные профили C03–C08 появятся только после приемки архива Валеры.

## 5. Контракт удаления для Swagger и Docker

DELETE /api/applications/{id} принимает JSON с единственным обязательным expected_version (текущий целый version заявки). Нужны действующая клиентская сессия, разрешенный Origin и X-CSRF-Token. Успех — 204 без тела. Устаревшая версия — 409 VERSION_CONFLICT; отправленная заявка, в том числе NEEDS_INFO, — 409 APPLICATION_NOT_DELETABLE. Недоступная/уже удаленная заявка — 404, роль банка — 403.

Это мягкое удаление: archived_at, увеличение lock_version и событие DRAFT_ARCHIVED фиксируются транзакционно под блокировкой. Восстановления через UI/API нет. Заявка исключается из списков/total и клиентского восстановления; чтение/изменение/отправка, отчеты, история и скачивание документов по прежним ссылкам недоступны. Связанные записи и приватные файлы физически сохраняются; автоматической очистки диска не добавляли. Удаление после начала LLM-генерации повторно проверяется перед сохранением отчета.

Диме: применять upgrade head до API; теперь это 0004_draft_archive. Фронт собирается `npm ci` → `npm run build`, результат frontend/dist. Режим по умолчанию — real. Сборку/раздачу SPA и proxy общего origin в Docker еще реализует Дима; для клиентских маршрутов нужен fallback на index.html. Секреты backend не передавать через VITE_*: эти настройки публичны и попадают в браузер. Подробный порядок БД — DOCKER_HANDOFF.md.

## 6. Режим с моками, проверки и остановка

`npm run dev:mock` / `npm run build:mock` используют отдельный браузерный симулятор, настройки frontend/.env.mock и hash-router. Он нужен для самостоятельной работы над UI и не доказывает работу с PostgreSQL, backend-авторизацией или настоящей LLM. Его данные не синхронизируются с БД. Для сквозной проверки и сдачи использовать real.

Проверено 23 октября 2026 года: обе сборки и TypeScript; 349 backend-тестов, включая PostgreSQL, миграции и удаление, прошли (три opt-in теста настоящей Ollama в этом прогоне пропущены). В отдельном браузере против PostgreSQL проверены вход/выход, сохранение/обновление страницы, расчет, явный AI-fallback, документы обоих контуров, автоматическое решение, удаление и 404, ручной дозапрос/отправка 2/решение, закрытие внутреннего комментария, пропущенный финансовый месяц и конфликт двух вкладок. При искусственной потере ответа submit повтор использовал тот же ключ и исходную версию без дубля; при ошибке сохранения отозванного согласия UI скрывал прежний отчет и варианты.

Остановка вручную: Ctrl+C в терминале Vite и Ctrl+C в терминале FastAPI. Службу PostgreSQL останавливать не требуется. Тестовые API/Vite и браузер, запущенные Codex для приемки, завершаются перед передачей; рабочие процессы пользователя не останавливаются.
